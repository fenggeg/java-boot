Why JavaBoot

多模块服务不用再在终端和 IDE 之间来回切。

本地联调 Spring Boot 多服务时，编译、启动顺序、日志、端口冲突和残留进程往往散落在多个工具里。Launcher 把它们收进同一操作闭环，用独立 daemon 托管进程生命周期。

Service Discovery

Spring Boot 模块自动识别

递归解析 Maven 聚合 pom，按 IDEA 标准只收 @SpringBootApplication 应用；工具包模块自动作依赖编入 classpath，不污染服务列表。

Build Strategies

三档编译，启动更快

Skip / CompileCurrent / CompileAll 按源码 mtime 与 classpath 缓存决策；离线优先 Maven 调用，弱网环境显著提速，改代码自动升档重编译。

Daemon Runtime

独立守护，UI 崩溃也不丢服务

java 进程的 spawn、日志、退出监控与 CPU/内存指标下沉到常驻 daemon；Launcher 重启后对账恢复，Job Object 防止残留子进程。

Logs & Metrics

日志聚合与端口监控

stdout/stderr 分流、级别过滤、正则高亮、虚拟滚动；端口占用扫描与冲突高亮，CPU / 内存实时展示。

File & Git

内置编辑器与只读 Git

Monaco 多标签编辑、Ctrl+P 快速打开；gutter 变更标记、Diff 对比、blame 悬浮——全部 git 调用在 Rust 后端完成，只读不改仓库。

Windows Native

为本地联调场景打磨

Tauri 2 + Rust + SQLite；环境变量按项目/服务注入，支持打包 fat jar 与应用自更新，贴合 Windows 开发习惯。

FAQ

启动前最常被问到的问题。

它是 Web 系统还是桌面应用？

它是面向 Windows 的本地桌面应用，用来管理本机 Maven 工程里的 Spring Boot 服务启动、日志与产物，不依赖云端。

只支持 Spring Boot 吗？

当前只支持 Spring Boot。判定与 IDEA 一致：packaging 为 jar/war 且存在 @SpringBootApplication 主类。公共 jar 不会出现在服务列表。

打包会停掉运行中的服务吗？

不会。服务用 exploded classpath 启动，JVM 不锁定 fat jar；打包失败也会恢复打包前状态。

UI 崩溃会不会把 Java 进程一起带走？

不会。自 v0.16.0 起 java 进程由独立 daemon 托管；Launcher 崩溃或重启后可对账恢复映射与日志。

能自动重启改代码的服务吗？

可以。按服务开启 auto_restart，watcher 维护脏标记，配合三档编译策略在变更后自动重编译并重启。

跨平台吗？

当前只在 Windows 路径验证（Job Object、taskkill 等）；macOS / Linux 暂未适配。
